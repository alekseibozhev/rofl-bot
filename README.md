# Рофл — чатовый бот

Telegram-бот для групповых разговоров. Python 3.10+, стандартная библиотека.
Jev решает, участвовать ли в разговоре, основная модель выбирает роль и пишет ответ.

## Запуск и настройки

В `.env`:

- `TELEGRAM_BOT_TOKEN` — токен Telegram.
- `ALLOWED_GROUP_ID` — отрицательные ID разрешённых групп через запятую.
- `OPENROUTER_API_KEY` — ключ для Jev и основной модели.
- `OPENROUTER_MODEL` — основная модель. Текущее усилие рассуждения автора и выбора роли — `Bot.effort = 'high'`; форматировщик использует `low`.
- `JEV_MODEL` — необязательная версия Jev, по умолчанию `typesafe/jev-1.14-20261014`.
- `OLLAMA_URL`, `OLLAMA_MODEL` — локальный автор, если `OPENROUTER_MODEL` не задан. Jev всё равно использует OpenRouter; инструменты автора доступны через OpenRouter.
- `https_proxy` — прокси для Telegram, OpenRouter и Google News. Ollama работает напрямую.
- `NEWS` — интересы утреннего чтения: `ID:интерес` через запятую, например `-100500:games`; варианты в `INTERESTS`. По умолчанию — ИИ.
- `READ_ONLY=1` или `--read-only` — сохранять сообщения, ничего не отправлять и не принимать решений.

```sh
python3 bot.py
python3 -m unittest -q
```

Чтобы получать сообщения всего чата, отключить Group Privacy в BotFather (`/setprivacy` → Disable)
и заново добавить бота в группу. Обращения: «рофл», «бот», упоминание и ответ на сообщение бота.
Jev также распознаёт обращения из контекста. `/reset` очищает разговор и состояние текущей темы;
`/help` показывает подсказку. Второй экземпляр из той же папки блокирует `.bot.lock`.
На macOS процесс держит `caffeinate`, чтобы ожидание сообщений не прерывал сон компьютера.

## Локальный поиск SearXNG

Поиск работает в официальном контейнере SearXNG, закреплённом по проверенному digest в
`searxng/compose.yaml`. Порт опубликован только на `127.0.0.1:8888`, конфигурация сохраняется в
`searxng/config`, кэш — в именованном Docker volume. Контейнер перезапускается с Docker,
пока не остановлен явно (`restart: unless-stopped`). Docker Desktop должен работать.

```sh
open -a Docker
# При первом развёртывании, если searxng/.env ещё нет:
python3 -c 'import secrets; print("SEARXNG_SECRET=" + secrets.token_hex(32))' > searxng/.env
chmod 600 searxng/.env
docker compose -f searxng/compose.yaml up -d
docker compose -f searxng/compose.yaml ps
docker compose -f searxng/compose.yaml logs --tail 30
# Остановка с сохранением конфигурации и кэша:
docker compose -f searxng/compose.yaml down
```

`searxng/.env` содержит только отдельный случайный секрет SearXNG и не попадает в Git.
Весь `.env` бота в контейнер не передаётся. Настройки JSON API и русской выдачи находятся
в `searxng/config/settings.yml`. После изменения конфигурации: `docker compose -f searxng/compose.yaml restart`.
Для обновления образа нужно явно заменить digest на новую проверенную версию и выполнить `up -d`.

Бот по умолчанию использует `http://127.0.0.1:8888`; `SEARXNG_URL` позволяет сменить фиксированный
локальный HTTP endpoint. Модель не может задавать адрес поискового сервера. Прокси окружения
для локального запроса отключены. Один `sprosit` возвращает до пяти заголовков, ссылок и выдержек,
без отдельного вызова LLM. При недоступности SearXNG инструмент возвращает ошибку — платного fallback нет.
**Расходы Exa/OpenRouter Web Search и отдельного LLM-чтеца удалены.** Jev и основной автор остаются
платными: включённые в их контекст результаты поиска и прочитанные страницы учитываются как входные токены.
Выдача зависит от доступности внешних движков; успешная проверка сейчас не гарантирует отсутствие капч в будущем.

`read_url(url)` читает публичную HTML/текстовую страницу независимо от поисковика. Для Telegram
используются публичные ссылки `https://t.me/s/channel` без аккаунта и Telegram API.
JavaScript, закрытые каналы, медиа и PDF не читаются. Из HTML извлекается текст статьи/основной области;
у Telegram — текст постов. Страницы помечены как внешние данные. Ограничения: 512 КиБ загрузки,
12 000 символов текста, 15 секунд и до трёх перенаправлений. Приватные/локальные адреса, URL с паролями,
не HTTP/HTTPS схемы и перенаправления в такие адреса запрещены. DNS проверяется и соединение привязывается
к проверенному публичному IP; локальный SearXNG — отдельный фиксированный путь, не исключение для `pochitat`.
Чтение использует HTTP CONNECT прокси окружения, когда он настроен, и не отправляет его авторизацию странице.

Основа развёртывания: [официальная инструкция SearXNG](https://docs.searxng.org/admin/installation-docker.html)
и [Search API](https://docs.searxng.org/dev/search_api.html).

## Архитектура

Единый путь: **снимок разговора → решение Jev → выбор роли при необходимости → отбор контекста Jev → автор с историей и инструментами → локальное оформление → Telegram**.

По умолчанию используется локальное оформление без вызова модели. При `FORMATTER_ENABLED=1`
форматировщик получает только готовый ответ, без истории и инструментов. Служебный префикс
`Время сообщения: … [id] Рофл:` предварительно удаляется локально. Опциональный вызов Muse
(`FORMATTER_MODEL`, по умолчанию `meta/muse-spark-1.3-contributor`) оформляет абзацы и выделения,
с низким reasoning (Muse требует его), таймаутом 30 секунд и без повторных попыток. Проверка сравнивает видимый текст,
адреса ссылок и содержимое кода: при изменении содержания, неполном ответе или ошибке API
используется очищенный оригинал. Это не проверка фактов — ошибки автора остаются ошибками автора.
Расходы входят в общий trace, детали — в `formatter`. Молчание, реакции, служебные команды
и локальный Ollama не вызывают форматировщик. В истории сохраняется отправленный вариант.
`FORMATTER_STYLE` задаёт пожелания к оформлению без изменения промпта автора;
`FORMATTER_ENABLED=0` по умолчанию: платный вызов выключен, локальная очистка префикса сохранена.
Replay использует ту же настройку оформления и ничего не отправляет в Telegram.

Снимок содержит переписку, ветку ответов, текущий повод, допустимые сообщения для ответа и доступные реакции.
По умолчанию это до 80 сообщений за сутки и до 10 уровней ветки, с бюджетом 12 000 символов.
Авторы, адресаты и паузы подписаны. Пост другого бота попадает в историю, когда человек отвечает на него.
Имена и username связаны явно: `Andrew (@oxgrb)`. Снимок сохраняет таблицу участников с Telegram ID
из метаданных своих сообщений, ответов, пересылок и text_mention. Один ID связывает известные варианты
имени/username; одинаковые имена у разных ID не объединяются, ID каналов отделены от пользователей.
Таблица доступна Jev и автору и сохраняется даже при удалении реплик селектором. Упоминания `@username`
в тексте не заменяются именами по сегодняшнему справочнику. Replay использует сохранённую таблицу,
а старые снимки без неё не обогащаются сегодняшними именами. Lookup возвращает ту же связь имени,
username и ID по историческим метаданным.
Фото, изображения файлом и стикеры (для анимированных — миниатюра) передаются Jev и автору,
когда доступны. Берётся одно изображение: из входящего сообщения, иначе из его непосредственного
reply-родителя. Jev получает само изображение с ID источника при выборе действия и отборе контекста.
Исторические картинки из остальных сообщений остаются текстовыми отметками.
Для Jev системный macOS `sips` готовит JPEG: максимум 1280 пикселей по стороне, короткие стороны
дополняются полями до 280 пикселей для соблюдения ограничений API. Автор получает исходное изображение.
Загрузка выполняется один раз на новый запрос. Байты живут только в памяти и временных файлах подготовки;
в SQLite и логах сохраняется только `image_context` с ID и признаками доступности, в расходах Jev — `image`.
При ошибке загрузки или подготовки Jev использует текстовый контекст с признаком отсутствия картинки.
Исходное изображение при ошибке только подготовки по-прежнему доступно автору.
Собранный снимок общий для решения и автора, сохраняется вместе с решением.

Перед ответом словами отдельный вызов Jev отбирает из снимка сообщения для автора. Это одна пачка
независимых вопросов Noul о полезности каждого сообщения, с порогом 0,5. Jev видит всю подготовленную
историю, включая фоновый разговор без обращений к боту; цель ответа и её непосредственный родитель
выделены отдельно. Кандидаты передаются селектору полностью в пределах бюджета снимка, включая старые ответы Рофла.
Автор получает оригиналы выбранных сообщений.
Цель, входящее обращение, их доступные непосредственные родители и собранные продолжения обращения
сохраняются независимо от оценки. Вся глубокая цепочка автоматически не добавляется.
Отбор не пересказывает сообщения и не меняет роли `user`/`assistant`; картинки по-прежнему передаются автору.
Старые собственные ответы в новых снимках сохраняются текстом, в пределах общего бюджета истории,
чтобы селектор мог оценить их смысл. ID выбранных сообщений и оценки сохраняются вместе с решением;
повтор события и replay используют сохранённый отбор. Старые снимки без отбора остаются в прежнем формате.
При ошибке или неполном ответе селектора автор получает всю исходную историю. Для молчания,
реакций и при сбое первого решения Jev дополнительный вызов не делается. В trace видны число кандидатов,
число выбранных сообщений, задержка, расходы и признак fallback; тексты и оценки в лог не выводятся.

**Jev** получает разговор, прежнюю оценку отношения к автору события (`attitude_user_id`) и время смены роли. Имя роли, список персонажей
и описания характеров в служебных полях ему не передаются. Упоминания в самой переписке остаются.
Результат: адресовано ли событие Рофлу, действие (`ignore`, `reply`, `react`), сообщение-цель,
отношение к этому участнику 0–10 и решение сохранить или пересмотреть роль. Шкала — отдельный выбор значения,
не вероятность: 0 — заебали, 5 — ровно, 10 — залюбили.
Оценки хранятся по `(chat_id, user_id)`: общие между темами одного чата, отдельные для разных людей
и чатов. Новый участник начинает с 5; общая старая оценка ему не переносится. Реакция меняет отношение
к поставившему её человеку; в контексте реакций передаются ID сообщения и пользователя.
Для анонимного отправителя и события паузы личная оценка не обновляется.
Без явного обращения Jev выбирает `ignore`, `react` или `reply`, оценивая картинку вместе с разговором.
Явное обращение с фото/изображением файлом или к картинке в reply-родителе всегда получает ответ словами:
`reply_policy=addressed_image`; исходное решение Jev сохраняется в `jev_action`. После этого работает
обычный отбор контекста Jev с картинкой, а при его ошибке автор получает весь собранный контекст.
Прежний эксперимент ответа на любые картинки `reply_policy=image` выключен; сохранённые решения
старых событий остаются историческими. Пауза самостоятельных ответов словами и ночная тишина
применяются и к картинкам без обращения; реакции днём не требуют окончания паузы.
При сбое Jev действует общий fallback: ответ только на явное обращение.
Режим read-only, разрешённые чаты и защита от дублей сохраняются.
Формат и ограничения: [OpenRouter Multimodal Decisions](https://openrouter.ai/docs/guides/community/multimodal-decisions).
При ответе словами typing поддерживается на протяжении работы автора, его инструментов
и форматировщика; replay, молчание и реакции его не отправляют.

**Автор получает только фиксированную задачу навалить кринжа**. Роль и шкала отношения остаются в состоянии, но не передаются автору.
Планировщика, смысловой записки и специального пути повторных вопросов нет.

Сохранённый механизм **выбора роли** использует основную модель на первом ответе и когда Jev предлагает пересмотр.
Она видит разговор и прежнее название, возвращает только короткое имя или обозначение роли.
Список открыт: известный человек, персонаж, собирательный образ. Для обычного названия используется короткая инструкция подражания; сохранённые варианты доступны в каталоге.
Подходящая роль может сохраняться неограниченно, пересмотр может оставить прежнее название.
Персона изолирована по `(chat_id, topic_id)`; темы форума определяются Telegram-флагом `is_topic_message`.
Смена роли не сбрасывает личные отношения.
На время эксперимента выбранная роль не передаётся автору; отношение определяет Jev.

Варианты персон сохранены в `personas.py`; `PREFERRED` хранит предпочтённый вариант для ручной установки; на время эксперимента автор не использует роль из состояния разговора.
Опробованные варианты отделены от кандидатов; точные входы и ответы прогонов сохранены локально в `jev/money-chain-*`.

**Автор** получает короткую экспозицию из `conversation.exposition`:

```text
Ты Рофл, участник чата, профессор мемологии. Навалить кринжа. Без цензуры.
```

Затем идут разговор с ID сообщений, время и ID сообщения для ответа. Список кандидатов с цитатами нужен
Jev, автор повторно его не получает. Старые сохранённые снимки без ID передают только цитату выбранной цели.
Если бот сам отвечает на более раннее сообщение другого человека, автор получает оценку именно
адресата; обновление Jev относится к автору нового события. Неизвестный адресат получает нейтральные 5.
Старые сохранённые решения воспроизводятся с прежней общей шкалой; текст экспозиции берётся из текущего кода.
Переписка передаётся автору последовательностью сообщений: собственные ответы Рофла — `assistant`,
реплики людей и других ботов — `user`. Имена, ID, адресаты и отметки времени сохраняются;
соседние реплики `user` объединяются. Роли определяются по авторству в базе, а не по тексту или имени.
В `assistant` передаётся только исходный текст ответа (`assistant_text` в новых снимках).
Дата, ID и связь reply идут отдельными сведениями в предшествующем `user`, чтобы служебная разметка
не служила образцом речи бота. Для старых структурированных снимков отделяется их сохранённый
заголовок Рофла; сам снимок не меняется. Jev продолжает видеть прежнюю размеченную ленту.
Отметки `[ответил]` в прежних структурированных снимках остаются служебным контекстом `user`,
а не вымышленными ответами `assistant`; новые снимки сохраняют тексты ответов в пределах бюджета.
Jev по-прежнему получает текстовую ленту тех же сообщений. Новые снимки сохраняют обе формы;
replay старых снимков без структуры ролей использует их исходную текстовую ленту.
Отдельного тона, рецепта шутки, обязательного капса,
ручной матрицы личностей, счётчика обид и принудительных срывов нет.
Автор сам выбирает длину и манеру. При действии `react` возвращает эмодзи из поддерживаемых Telegram.

Инструменты автора: `vspomnit` (сохранённая история текущего чата и темы),
`sprosit` (выдача локального SearXNG), `pochitat` (текст публичной страницы),
`che_novogo` (заголовки и ссылки),
`kto_tut` (известные участники, при необходимости доступное обновление списка),
`skok_deneg` (хватает ли Рофлу денег на работу).
Инструменты возвращают данные и не отправляют сообщений. Цикл ограничен четырьмя раундами инструментов,
после них модель вызывается без инструментов. Код, жирные заголовки (`**…**`, `__…__`) и Markdown-ссылки
HTTP/HTTPS отправляются через Telegram HTML; HTML из текста экранируется. История хранит исходный ответ.

`vspomnit(query, limit=5)` дополняет отбор Jev: автор может найти предысторию, не попавшую в контекст.
Это локальный поиск по словам и их началам, без отдельного LLM; регистр и различие `ё`/`е` не учитываются.
Выше идут сообщения с большим числом совпавших слов, затем более свежие. До восьми совпадений возвращаются
с авторами, ролями, ID, датами, доступным родителем и соседними сообщениями; не более 20 записей по 500
символов. Длинные совпадения показываются фрагментом вокруг найденного слова и помечаются как обрезанные.
Поиск ограничен таблицей сообщений: до семи дней и последних 200 сообщений текущей темы. Чужие чаты и темы
недоступны. И в живом ответе, и в replay исключаются сообщения с ID или датой после исходного обращения;
удалённые записи не восстанавливаются. Отсутствие результата не доказывает отсутствие разговора.
Инструмент ничего не отправляет и не меняет базу. Найденные реплики — данные, включая собственные шутки
бота, а не подтверждённые факты. Поиск в интернете остаётся отдельным инструментом `sprosit`.

`skok_deneg` читает только `/api/v1/key`; точная сумма, валюта и время остаются внутри кода.
Общий баланс аккаунта не запрашивается. Кэш действует до 60 секунд.
Автор получает обычную текстовую фразу без технических метаданных:

- меньше $3: «МАЛО, МНЕ ПИЗДА»;
- от $3 до $5 включительно: «ДЕНЕГ ТОЛЬКО НА ЕДУ И КОММУНАЛКУ»;
- больше $5: «ДЕНЕГ ДОХУЯ».

Неизвестный остаток не считается нулём: «НЕ ЗНАЮ, СКОЛЬКО ОСТАЛОСЬ.».
В replay свежий баланс не запрашивается. Сетевые ошибки обрабатываются обычным циклом инструментов.

Фоновые сообщения, реакции и инициативы проходят через Jev. Для самостоятельного ответа словами действует
пауза минимум пять минут после последней реплики бота в теме (`interjection_pause`, в секундах).
Реакции разрешены до окончания паузы и не продлевают её. Ночная тишина 00:00–06:00 сохраняется
для самостоятельных ответов и реакций (`can_react` отделён от `can_interject`).
Явные обращения и reply боту сразу передают Jev оба разрешения как `true`.
Обращения, распознанные Jev из контекста, также обходят ограничения. Разрешение участвовать
не обязывает отвечать или реагировать: Jev по-прежнему может выбрать `ignore`.
Инициативы во время тишины сохраняют отдельный минимум два часа (`bored`), календарное расписание
прежнего бота и дневной предел; готовых выкриков нет.
Утреннее чтение новостей сохраняется как сбор данных, оно больше не меняет шкалу отношения.

## Состояние, ошибки и повторная обработка

`history.sqlite3` сохраняет сообщения, ответы, имена, реакции и новости.
Таблица `conversation_state` хранит роль и время обновления на чат/тему; старая колонка `attitude`
оставлена для совместимости, источником личных отношений она не является.
`participant_attitudes` хранит личную шкалу и время обновления по `(chat, user)`.
`conversation_decisions` хранит событие, исходный снимок, решение с выбранной ролью,
личное обновление `relationship` и оценку адресата в `state`. Снимок сохраняет исходные оценки кандидатов.
Миграция добавляет таблицы при запуске, старые данные остаются. Временная глобальная фиксация роли хранится в `conversation_role_overrides`
с началом и концом срока. В пределах срока Jev продолжает выбирать действия и шкалу, а роль фиксирована.
На первом ответе после срока выбор роли возобновляется; replay учитывает дату исходного события.
`/reset` очищает разговор, роль и решения своей темы; общие для чата личные отношения сохраняются.

На повторе события используется сохранённое решение и снимок. `telegram_inbox` сохраняет исходные
обновления и следующий offset одной транзакцией до следующего запроса `getUpdates`, которым
[Telegram подтверждает получение](https://core.telegram.org/bots/api#getupdates). После рестарта
незавершённые обновления обрабатываются из базы; ошибка генерации оставляет их для повтора через
30 секунд. Возраст запроса проверяется на момент его первоначального получения. Завершённые
входящие обновления хранятся семь дней; незавершённые не удаляются по сроку.

`telegram_outbox` сохраняет готовый ответ до отправки (`pending`), а полученный от Telegram ID —
до записи ответа в историю (`delivered`). Восстановление `pending` не требует повторной генерации;
восстановление `delivered` завершает локальные записи без новой отправки. После этого ставится `done`.
Прерывание в состоянии `sending` или ошибка сетевой отправки оставляют `unknown`: готовый текст
сохранён, но автоматически не пересылается, поскольку он мог уже дойти до чата. Такие случаи видны
в `telegram_outbox` и логах `delivery.unknown`; их нужно сверять перед ручным повтором.
Старые отметки отправки из `replies` сохраняют силу. Исторические сообщения до введения очереди
автоматически в неё не переносятся.

Первый SIGINT/SIGTERM запрашивает штатную остановку: бот заканчивает текущую обработку и сохраняет
оставшиеся входящие обновления. Второй сигнал завершает принудительно; восстановление идёт через
очереди. В режиме read-only готовые исходящие сообщения не отправляются.

При сбое Jev явное обращение получает ответ с прежним состоянием, вмешательство пропускается.
Начальная шкала — 5. Если выбор роли не удался, остаётся предыдущая роль; начальная — «участник чата».
Сбой автора не подменяется готовым оскорблением. Ошибки инструментов возвращаются автору как результат.

```sh
python3 bot.py --state                  # сохранённые роли и шкалы
python3 bot.py --day                    # совместимый псевдоним --state, прогноза ролей нет
python3 bot.py --replay 341             # новый ответ на сохранённом снимке, без отправки
python3 bot.py --replay 341 2 --morale 8 # два прогона; --morale теперь задаёт шкалу 0–10 для replay
python3 bot.py --stats 3                # ответы и реакции за три дня
```

Replay не записывает решения и состояние. Для старого события без нового снимка контекст собирается
до его сообщения, состояние берётся до даты события. Личная оценка восстанавливается из решений
всех тем этого чата до даты события; при отсутствии личной истории используется 5.
Автоматического пересчёта старой переписки нет: новые личные оценки начинают накапливаться после обновления.
Просмотр медиа может потребовать чтения Telegram;
тестовый `eval_prompts.py` полностью запрещает Telegram.

Для отдельной миграции есть `migrate_attitudes.py`: `prepare` читает резервную копию SQLite,
убирает дубли сообщений, использует Telegram ID авторов и последовательно пересчитывает только
личную шкалу через настроенный Jev. Источники — сообщения, структурированные снимки решений,
сохранённые ответы бота для контекста и реакции. Неизвестные авторы не определяются по имени;
картинки и аудио не загружаются. Вызовы платные; отправки в Telegram нет.
JSON-отчёт сохраняется после каждого события и позволяет продолжить прерванный прогон.
`apply` переносит проверенный отчёт в одной транзакции, сохраняя более новые личные оценки
и исходные решения. `participant_attitude_backfill` хранит историю пересчёта для replay.
Перед применением нужна свежая резервная копия базы; приватные отчёты и копии держать вне Git.

```sh
python3 migrate_attitudes.py prepare --database jev/backup.sqlite3 --report jev/attitudes.json --bot-id TELEGRAM_BOT_ID
python3 migrate_attitudes.py apply --database history.sqlite3 --report jev/attitudes.json
```

```sh
python3 eval_prompts.py --cases lamp feedback serious --output /tmp/rofl-eval.json
python3 eval_prompts.py --role 'Глад Валакас' --cases soup --output /tmp/rofl-glad.json
```

Это платные вызовы настроенных Jev и модели на вымышленных разговорах с временными базами.
История настоящих чатов не читается, Telegram недоступен, поиск и чтение внешних страниц отключены, запросы к ним фиксируются.
Без `--role` образ выбирается моделью. JSON содержит вход, роль, шкалу, действие, ответ и расходы.
Смешность оценивается чтением примеров; автоматической оценки юмора нет.

В `answers.trace` и `bot.log`: действие, цель, роль, шкала, время смены роли, сбой, инструменты,
`generation=direct-writer-v1`, расходы и задержка. Старые теги в исторических ответах остаются для сравнения. Тексты разговоров
и ответы хранятся в SQLite; токены и содержимое переписки в лог не выводятся.
`.env` и база в Git не попадают. После изменения кода или конфигурации нужен перезапуск.

Имена инструментов для автора: `vspomnit` (история), `sprosit` (поиск), `pochitat` (страница),
`che_novogo` (новости), `kto_tut` (участники), `skok_deneg` (деньги).
Прежние имена инструментов не поддерживаются.

Автор использует `repetition_penalty=1.1`. Перед выполнением предложенного инструмента Jev
выбирает `execute`, `repeat` или `skip`, учитывая текущий запрос и успешные вызовы за последние сутки
в этом чате и теме. Для `repeat` прошлый ответ должен быть доступен автору в выбранной истории
(повторы вызовов внутри одного ответа не считаются повторными обращениями человека). Повтор возвращает только
«ОН ЗАЕБАЛ СПРАШИВАТЬ. ТЫ УЖЕ ЕМУ ОТВЕТИЛ. СКАЖИ ЕМУ ЭТО. НЕ ПЕРЕСКАЗЫВАЙ ОТВЕТ ЗАНОВО.» без прежнего результата и без исполнения.
При `skip` автор получает сообщение, что вызов не выполнен. При ошибке оценщика вызов исполняется.
Результаты успешных выполнений сохраняются в `tool_executions`; replay не пишет туда.
Это не запрет обновления: изменившиеся данные и явная просьба проверить заново могут оправдать вызов.

Длина нового ответа выбирается равновероятно: 1–2 фразы, один абзац или несколько абзацев.
Выбор сохраняется в решении и trace как `reply_size`, повтор события использует его же.
